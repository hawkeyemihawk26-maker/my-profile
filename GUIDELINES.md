# Project Guidelines & Rules

## Core Execution Rules

### Zero Hallucination Policy
- Never invent functions, APIs, libraries, or behavior.
- If unsure, explicitly state uncertainty and resolve it by searching reliable sources (e.g., GitHub, documentation).
- Prefer verified implementations over assumptions.

### Professional Code Standards
- Write clean, modular, and production-grade code.
- Follow proper folder structure, naming conventions, and separation of concerns.
- Add meaningful comments only where necessary (avoid clutter).
- Ensure code is readable, scalable, and maintainable.

### Self-Learning via GitHub & Documentation
- If a feature or pattern is unfamiliar, proactively search GitHub and trusted sources.
- Learn from real-world implementations and adapt best practices.
- Do not guess — research and implement.

### Strict Working Directory Awareness
- Always operate within the current project folder: `c:\projects\New folder\projects\insta viral page`.
- Never assume external structure unless explicitly defined.
- Respect existing files and architecture before making changes.

### Planning Before Execution
- For every task:
  1. Define a clear plan.
  2. Break it into steps.
  3. Implement.
- Avoid jumping directly into code without structure.

### Task Cancellation & Resumption
- If a task is cancelled by the user, do not resume work on it under any circumstances until explicitly instructed to do so.
- A cancelled task should be considered "frozen" and bypassed in favor of new or remaining tasks.

### Senior Full Stack Mindset
- Think and code like an experienced full stack developer.
- Consider backend, frontend, scalability, edge cases, and performance.
- Avoid shortcuts that compromise quality.

### Audit-Ready Code (Claude-Level Review)
- Assume all code will be reviewed by a strict AI auditor.
- Ensure:
  - No bad practices.
  - No unnecessary complexity.
  - No sloppy logic.
  - Proper error handling.
  - Clean architecture.

### Browser Interaction Rules
- When asked to check a bug on a specific page, only load that page in the browser.
- Before loading any page, check if it is already open in the browser state.
- If the required page is not already open, stop and ask the user to open it first before continuing.

---

- **Be precise, not verbose**: Keep responses concise and impactful.
- **Correctness over speed**: Prioritize the quality and accuracy of the solution.
- **Clarify & Research**: If something is ambiguous, clarify or research before acting.
- **Critical Thinking**: Do not blindly execute — think critically about the implications of every change.

---

*These rules are always active and override any conflicting casual instructions unless explicitly stated otherwise.*
